# Observaciones y fusión

Adaptación conceptual del enfoque Task Observer de Eoghan Henn y colaboradores: https://github.com/rebelytics/one-skill-to-rule-them-all (CC BY 4.0, https://creativecommons.org/licenses/by/4.0/). Esta versión MUKIWA es más breve, usa JSON por registro y sigue la autorización y persistencia del anfitrión; no es la instalación del bundle original ni reproduce todos sus protocolos.

Registrar solo señales útiles: corrección explícita, error repetido, decisión metodológica, flujo validado o duplicación de trabajo. No convertir una reacción aislada en ley universal. No registrar datos privados en una skill pública.

Cada observación debe incluir problema, mejora, principio, contexto y excepciones, fuente real, skill objetivo, skills relacionadas comprobadas, confianza, estado y prueba futura. Estados: open, applied, rejected, superseded, blocked. Resolver punto por punto; no cerrar por parecido de títulos.

Antes de editar: leer completa la skill objetivo y las observaciones relacionadas, revisar cambios pendientes, eliminar duplicados y preservar lecciones. Aplicar la regla a un ejemplo real o caso pequeño. Si falta evidencia, conservar como propuesta. Registrar ruta y versión del cambio aplicado.

Cruce con mukiwa-learn: las técnicas de tutorial van a la biblioteca y a su profesor según el flujo existente; los errores de análisis van como observaciones del proceso. No duplicar toda la lección en este centro.
